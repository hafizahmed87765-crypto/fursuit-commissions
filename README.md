# FursuitCommissions.com

Code rebuild of fursuitcommissions.com (previously WordPress + Elementor + WooCommerce on Hostinger).
Next.js 16 (App Router) · React 19 · Tailwind 3 · TypeScript.

WooCommerce **stays** as the shop backend: products are snapshotted into this repo, and
"Add to cart" hands off to the WooCommerce cart/checkout (PayPal etc. unchanged).

## Commands

```bash
npm install
cp .env.example .env.local   # fill in values
npm run dev                  # http://localhost:3000
npm run build && npm start   # production
npm run lint && npm run typecheck
npm run sync                 # re-pull products, categories & gallery images from WooCommerce
```

## Structure

| Path | Purpose |
|------|---------|
| `src/content/site.ts` | Business facts, nav, announcement, prices, process, reviews (edit here) |
| `src/content/faqs.ts`, `portfolio.ts`, `legal.ts` | FAQs, curated gallery, Terms of Service |
| `src/data/*.json` | WooCommerce snapshot (generated by `npm run sync`, don't hand-edit) |
| `public/media/` | Optimised WebP copies of product + gallery images |
| `src/app/api/inquiry/route.ts` | Quote / repair / contact submissions → SMTP email with attachments |
| `src/proxy.ts` | 410 Gone for the injected spam URLs (`/blog/*`, old sitemaps) |
| `next.config.mjs` | 301/308 redirects from old WordPress URLs |
| `docs/` | Design system, content to-do, competitor notes |

## Environment

See `.env.example`. Required for production:

- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `OWNER_EMAIL` — without them forms return
  503 and show a "not sent" message (never a fake success).
- `NEXT_PUBLIC_WOO_ORIGIN` — WordPress/WooCommerce origin for cart & checkout. When this site takes
  over `fursuitcommissions.com`, move WordPress to a subdomain (e.g. `shop.fursuitcommissions.com`)
  and set it here. Empty = buy buttons replaced with "Ask about this item".
- `NEXT_PUBLIC_GTM_ID` — existing GTM container (`GTM-57MGG25L`); loads only after cookie consent.

## Analytics events (dataLayer)

`service_selection`, `commission_planner_start`, `commission_planner_complete`, `quote_form_start`,
`quote_form_submit_success`, `repair_form_submit_success`, `contact_form_submit_success`,
`product_view`, `add_to_cart` (fires on the hand-off click). Success events fire only after the
server confirms delivery. `checkout_start` / `purchase` happen in WooCommerce and should be tracked
there (Site Kit / WooCommerce GA integration), not here.

## Deploying (outline)

1. Clean the WordPress install first (see security note below).
2. Move WordPress to `shop.` subdomain; set WooCommerce "Site Address" accordingly.
3. Deploy this app (Vercel, Netlify or Hostinger Node hosting) on the main domain with the env vars.
4. Submit the new `sitemap.xml` in Search Console; remove the old Yoast sitemaps.

## ⚠️ Security note — old WordPress site

The live WordPress site is compromised (found Oct 2026): ~5,500 injected casino spam posts under
`/blog/` (listed in the Yoast sitemaps) and French casino text injected into 15 pages on
2026-06-13. Product data was clean. Before keeping WordPress as the shop backend: restore from a
pre-June backup or clean it, update core/plugins, remove unknown admin users and plugins, rotate all
passwords and keys, and run a malware scan (Wordfence is installed).
